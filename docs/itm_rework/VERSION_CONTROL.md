## 恢复重复快照

[分类及SHA映射](version_control_snapshot_20261010_v1.json)记录规范来源、归档位置和字节数。以下默认只检查，不写文件：

```bash
python scripts/restore_git_archive_snapshots.py
```

在新checkout需要旧归档路径时：

```bash
python scripts/restore_git_archive_snapshots.py --apply
```

脚本先核验全部规范来源SHA，再复制缺失副本；已有且不同的文件不会覆盖。3项CPU测试覆盖dry-run/恢复、先全量检查再写入、路径边界。302副本的当前完整dry-run核对通过。

恢复脚本只恢复字节相同的副本，不能生成权重、数据、receipt或完整实验缓存。报告及索引中的本机绝对路径仍是历史来源记录；新机器运行需要另行准备数据/模型资产。本地`outputs/`及完整归档应有独立备份，Git中的SHA索引本身不是这些产物的备份。

1. 忽略边界、分类清单与恢复脚本/测试。
2. 历史B0诊断实现、冻结协议、失败/负结果及精简证据。
3. 扩展数据、20/100epoch训练/采样及共同对照。
4. 头部主线指标、局部监督候选和全部32val评价。
5. 缓存动作审阅前端、导出/绘图入口。
6. 最新交接/证据索引、投稿推进和原始三任务书。

各提交只纳入所属文件，完整本地产物不移动。完成后核查工作区、暂存区、忽略命中、SHA与提交范围；论文LaTeX不在本轮改动范围。
