## 0. 三个会话共同遵守的协作契约

### 0.1 范围、目标与证据状态

本轮只研究**完整片段输入的离线全身动作生成**，分别使用 `head`（槽位 4）或 `wrists`（槽位 0、1）两种配置。不默认增加 head+wrists 联合配置，不扩展任意佩戴组合，不做在线跟踪、实时系统或未来动作预测。

主场景是**局部表演驱动的虚拟角色动作创作**：用户录制局部运动，并用文本指定最终目标动作或编辑意图；输出不必等于录制时真实发生的完整动作，但应保留输入中实际可观测的惯性特征。文本和 IMU 不预设为严格独立的“语义/物理”变量。

三条主证据是：① IMU 带来文本未确定的实例信息；② 在已确认相容的组合上，文本实现目标编辑且不破坏观测；③ 所提机制在同一 backbone 和明确预算下优于简单替代实现。必须由**同一个最终模型**支撑联合能力，不能拼接不同 checkpoint 的优点。

## 3. 核心任务与应用场景：正文必须回答清楚

### 3.1 为什么用户同时需要两种输入

用户提供 IMU，是为了保留**一次具体局部表演**；提供文本，是为了指定最终动作或修改传感器不足以确定的部分，而不是每次随机生成，也不必忠实复制录制时的完整人体动作。

用下面的逻辑重写，而不是从模型发展史开头：

> 在离线虚拟角色动作创作中，用户希望保留一段头部或双腕表演的运动特征，同时用语言指定最终全身动作。仅用文本难以复现一次具体表演；仅用稀疏惯性观测又不足以唯一确定完整动作。我们关注如何在不破坏已观测运动的前提下，利用文本选择或编辑仍有歧义的动作内容。

这是场景与研究动机，不是已证明的方法效果。用户是否只需表演一小部分、某一属性是否能自由编辑，要有具体条件与证据，不能在场景例子中预先保证。

### 3.2 边界直接写入正文

完整片段输入；head-only 或双腕分别研究；离线生成；文本可为目标语义/编辑而非仅原动作描述。输出可以偏离原始全身 GT，但应满足声明的观测容差及语义/质量要求。不研究无条件恢复唯一真实动作、在线延迟或未来预测。

VR/可穿戴是动机，不代表本文已经使用了真实 VR 6-DoF 跟踪。实际输入是原始 IMU、融合姿态还是世界系去重力加速度，按 02 契约写清。它与关节位置、手柄/头显 6-DoF 位姿、轨迹提示不是同一种信息预算。

### 3.3 模态关系不能过度整齐

避免“文本只负责高层语义，IMU 只负责底层物理”。文本可能指定节奏/速度，IMU 可能强烈透露动作类别，两者存在冗余和冲突。

更准确的表述：**IMU 限制可观测的运动成分，文本在相容条件下选择或编辑观测尚未充分确定的内容。**“未观测成分”不是“没戴设备的关节”；身体运动链存在耦合。

正式区分：相容性、信息增量、当前模型能力。可以引用 02 的可行集合定义，但不要宣称已经精确求解所有文本—IMU 组合的存在性。

固定头部时的摆臂、转向、快慢和步幅，根据具体观测判定相容/冲突；不能凭词语给固定标签。相容组合的模型失败既可能是表示/训练/bug，也可能是 teacher 不理解文本，不直接否定任务意义。

## 4. 逐章重构方案

### 4.1 `0_abstract.tex`：写清任务、机制与证据，不写泛泛愿景

摘要按五步组织：场景需求 → 具体困难 → 最终实际方法机制 → 评价协议 → 已支持结果及边界。

删减“统一、可扩展、面向不同基座的通用框架”这类尚缺独立证据的主张。轻量需有参数/更新规模/成本；冻结权重不保证语义完全保留；可迁移需有实际接口和稳定结果。

方法未确定前可用显式研究稿占位：

```text
【目标方案，待验证】我们研究通过相容编辑监督保留语义相对响应，
并考察观测敏感性的生成引导是否改善联合满足。
【结果待更新】最终方法、样本规模和效应量以 evidence index 为准。
```

没有数据就不写“显著”“稳定”“首次”“保持全部性能”。未知数用 `TBD`，不要根据理想状态生成合理-looking 数字。

### 4.2 `1_introduction.tex`：推荐五段主线

**第一段：场景。** 局部录制加离线文本编辑；为什么同一个用户需要这两个入口。

**第二段：单模态不足。** 文本不能指定一次具体表演；稀疏观测不唯一决定全身动作。强调输出目标，不以“生成不是重建”的名字区分。

**第三段：真正困难。** 条件可能相容、冗余或冲突；不同物理表示难对齐；新控制可被忽略也可破坏文本响应。引出联合成功而非两个输入都会造成变化。

**第四段：方法机制。** 仅描述 01 已实现或明确标注 proposed 的机制；编码器、adapter 为实现基础，不自动列为核心创新。

**第五段：证据与范围。** 配对实例控制、相容编辑、必要性消融三条证据；head/wrists、离线边界；跨 backbone 作为补充范围分析。

贡献压缩为不超过三项，分别对应任务/协议、实际有效机制、实验发现。方法尚无有效增量时，不把“设计多个模块”改写成贡献；相容协议本身若只是简单规则，也不能夸大为普适 benchmark。

### 4.3 `2_relatedworks.tex`：最接近工作提前，按输入和输出要求区分

建议顺序：语言与稀疏惯性联合建模 → 稀疏空间/VR 条件与动作编辑 → 预训练生成和条件适配。文本生成模型年代史压缩，保留支持本文方法选择所必需的部分。

需要核查的一手工作包括 Ego4o、Spatial-Related Sensors Matters、EgoLM、DiffusionPoser，以及 OmniControl/GMD、MDM/MotionLab、ControlNet。若采用 C 分支，还需核对 DDNM/测量一致性投影等基础。它们是查证列表，不是许可不读原文就写结论。

建立内部 related-work 对照表，列出：实际输入（惯性/位置/6-DoF）、文本角色、输出目标、是否随机生成、是否测试反事实组合、是否评价联合满足、数据协议。没有证据的字段写“未确认”，不能写成“无”。

“已有工作没有联合使用文本与 IMU”必须删除。“他们只是重建、我们是生成”也不能独立承担新颖性。区分用户目标编辑、可行输出集合和评价协议；避免把所有多模态系统放进同一任务后宣称更强。

外部工作事实、当前代码/checkpoint 可用性、年份和 venue 需从作者页面、论文或官方仓库核查；过期的“没有实现”说法不能沿用。无法联网时标注待核实，不补造引用。

### 4.4 `3_method.tex`：从实验日志改成最终方法

推荐组织：

1. Task and observation contract：输入输出、两配置、物理单位与坐标、有效 mask、时间与可行性。
2. Backbone adaptation baseline：身份保持编码、条件门控、冻结边界和零初始化；注明它是基础而不是独占创新。
3. Effective mechanism：最终 B 或 C 或两者中被证据支持的部分；每项对应明确要解决的问题。
4. Training and inference：区分配对 diffusion、编辑监督、观测项；四分支或最终采用的 guidance 与实现一致。
5. Cost and scope：参数、teacher/投影额外成本、依赖观测认证范围。

历史 MDM 方法正文为三分支，后续实验已有四分支。明确不同协议版本，不让同一主公式和主实验描述互相冲突。“Independent Guidance”宜改成双条件效应分解/条件 guidance，不能暗示统计独立或物理完全解耦。

写明输入是安装顶点世界系线加速度及全局姿态（以 02 最终契约为准）。生成输出若只支持 joint proxy，则写清观测算子的不足；不要笼统叫“IMU consistency loss”。

将训练 epoch loss 列表、checkpoint 文件名、磁盘路径、Stage 时间线、无必要的超参表移到 implementation details/附录。所有辅助损失给实际定义；不把只在局部有效的 velocity/jerk 预定为必要组件。

B 的相对响应监督是研究方案，不能无证据写成“解决条件冲突”；C 为局部软约束更新，不是全局精确可行性保证。旧 ControlNet/零空间思想需正确归因。

### 4.5 `4_experiments.tex`：按问题组织，不按开发日期排列

主结构：

- Data / protocols / implementation：来源分组、开发与独立测试、相容构造、指标和随机预算。
- Q1：在同类运动和可比条件下，IMU 是否提供实例级约束？
- Q2：同一模型在相容组合中，能否同时满足文本、观测与质量？
- Q3：这种收益是否优于简单融合、绝对 anchor 或普通测量梯度？
- Scope / failure analysis：head 与 wrists 区别、冲突/uncertain、必要的迁移和真实 pilot。

正文主要结果尽量收敛为三张核心表加一张可选范围表：配对控制/质量、相容编辑联合成功、机制消融；真实或跨 backbone 作为可选第四张。样本规模与完整细节放统一协议表或附录，不重复十余张历史表。

保留现有多种子/置信区间结果，但证据状态按 02 复核；不要把 diffusion seeds 写成独立训练重复。不能用 Stage-1 的语义优点与 Stage-2b 的平滑优点合成同一方法兼得两者。

**移入补充材料而非删除：**线性/MLP/DistilBERT 的早期重建历史，Direct-V3/V4 预筛，大部分非主 backbone 迁移过程、完整 guidance 网格、debug 日志。保留重要负结果及作用范围，不需要让每个失败分支占正文一节。

所有数字来自 evidence 索引；有意编辑后的动作不应继续用原始完整 GT MSE 作为唯一成功标准。配对重建可以公平报告 MPJPE，不必禁止随机生成模型参与，但明确平均/best-of-K和输入预算。

### 4.6 `5_discussion.tex`：区分三类限制

- **任务观测限制：**某些变量确实不能从给定观测唯一确定；不是模型错误。
- **表示/算子限制：**生成表示、SMPL 拟合、安装点或标定导致无法验证完整观测；不是任务本身不可能。
- **当前方法限制：**本轮数据、网络、损失、预算下某些编辑不可靠；不能泛化到所有方法。

允许写“当前实现观察到的平滑性与部分语义响应取舍”，不要写成“不可避免的系统性权衡”，除非有更强论证。单次预筛失败不是对整类 attention/contrastive learning 的反证。

Nymeria 3 条可保留为 pilot。真实硬件或 participant-disjoint 结果没有完成前，不写成已实现的跨域泛化。

### 4.7 `6_conclusion.tex`：只总结同一最终版本的证据

每一句回指 claim 账本。区分 head 与 wrists、joint proxy 与真实观测、平均收益与逐样本可靠率、采样稳定性与训练稳定性。可以提出后续真实硬件验证，但不提前许诺实时能力或普遍迁移。

## 5. 必须直接修正的旧表述

| 旧表述风险 | 正确处理 |
|---|---|
| 换 IMU 后输出变了，所以控制成功 | 只能说明敏感性；有效控制还需目标观测/时序/属性朝正确方向变化。 |
| 74/100，CI 65%—82%，所以总体可靠率超过 70% | 仅点估计过线；区间包含 70%，不能确认总体超过该阈值。 |
| paired 与 zero 无显著差异，证明模型只学到固定偏置 | 非显著不能证明等价或机制；需要直接 intervention/残差审计。 |
| 冻结 backbone 保证不改变文本生成路径 | 初始等价不等于训练后等价；null bias、dropout/执行路径需 01 实测。 |
| 两个 guidance scale 独立，说明语义与 IMU 解耦 | 可调参数与效应分解不是统计或物理解耦证明。 |
| jerk 更低，动作必然更自然 | 检查收缩/静止、幅度、足滑和盲评；不要将比值越低一律视为好。 |
| 生成模型只有关节 proxy，但报告严格 IMU 一致性 | 使用准确名称；姿态/安装点重合成认证未通过时降低主张。 |
| Stage-1→Stage-2b 变好，所以三个新损失有效 | 续训等因素混杂；以同起点同预算的严格消融说明机制。 |
| V3/V4 预筛失败，证明身份保留/条件对比没有用 | 限定为当前实现与预算未见足够收益；训练检索率也不是生成控制。 |
| 所有文本组合都应成功；速度/转向失败等于语义能力失败 | 先区分组合相容性、teacher 能力、观测冲突与实现问题。 |
| 同一方法在 head/wrists 和多个 backbone 上都可靠 | 逐配置与模型声明证据，平均改善不能代替每样本可靠性。 |
| 没有看到官方 checkpoint，因此相关方法不存在可复现实验 | 当前事实重新查证；缺少比较需明确解释，不能发明数字或过期断言。 |

这些是需要逐项核查和修订的风险，不是要求不读当前正文就机械替换字符串。

## 6. 目标稿与证据稿：允许先写理想设计，禁止隐藏结果状态

用户允许先按理想结构组织，再根据最终方法删改。采用如下方式满足这一需求：

**目标层**可以先完整写：应用、任务定义、相容性、拟解决机制、实验问题和预期交付。

**实现层**引用 01 的模型卡：已经有哪些模块、代码版本、输入输出和成本。

**结果层**只引用 02 的 evidence：实验是否运行、哪些配置支持、有什么失败和缺口。

不能在 PDF 正文写“实验表明稳定有效”，只在 `%` 注释里写“其实还没做”。必要时实现一个 draft 可见标记，例如 `\claimtodo{待验证结论}`；release 构建检测仍有 pending claim 时应告警/失败，而不是简单把提示隐藏。

每个核心结论建立 `docs/itm_rework/paper/claims.yaml` 或同等账本：

```yaml
claim_id: C2_compatible_editing
status: proposed # implemented / evaluated / partial / supported / rejected
scope: [head, wrists]
manuscript_locations: [abstract, introduction, experiments, conclusion]
method_commit: null
evidence_ids: []
wording_now: "目标是在相容组合上同时满足语义与观测。"
wording_after_verification: null
missing_evidence:
  - frozen_compatibility_manifest
  - same_model_joint_success
  - independent_semantic_check
limitations: []
```

这些是**论文 claim 状态**，不要与 02 的原始 evidence 验证状态混用。`implemented` 只代表代码存在；`evaluated` 只代表跑过实验；都不自动等于 `supported`。

建议核心 claim：C1 双腕/单头实例信息（分别建 scope）；C2 相容编辑联合满足；C3 机制优于简单基线；C4 输出观测可验证范围；C5 真实/跨 backbone 范围；C6 成本。没有 evidence 的 claim 不出现在确定性结果段。

## 8. 引用、编译与格式检查

逐条核对 bib key、作者、题名、年份、venue/arXiv ID；正文比较只使用已读一手资料。对“最新”“更强”等时间敏感措辞特别谨慎，不要求为凑新颖性追所有新模型。

保持现有 IEEE/中文编译框架，除非用户另行指定投稿目标，不自作主张改成另一会议模板。不填虚构作者、单位、期刊或投稿状态。

核查 XeLaTeX/BibTeX 或现有 latexmk 构建是否可用。编译可用则检查交叉引用、缺图、超宽表、断行和页数；不可用则给静态检查和未验证清单，不写“编译通过”。将 `%` 中的证据备注与 PDF 可见状态同时检查。

补充材料可以在 `paper/latex-ITM/` 内采用现有习惯新增文件，并更新实际入口；保留历史结果出处和模型 ID，不因移出正文丢失负结果。只删除重复叙述，不删除原始实验记录。

## 9. 与方法/实验会话的交接顺序

**第一轮，不等新训练。** 完成场景、任务、章节结构、旧数字状态标注、related-work 查证清单、claim 账本与图表规范。保留方法段显式 pending，而不是等待所有实验完成才开始写。

**第二轮，接收 B0 与观测契约。** 按 01 模型卡修正文档和 CFG；按 02 的认证范围重命名指标，更新实验协议。出现代码与稿件不一致，提具体问题，不自行决定真实行为。

**第三轮，接收冻结候选证据。** 插入对应表图和精确结论；删去未有效模块及不受支持的理想主张；重查摘要、引言贡献、讨论、结论是否一致。测试后新产生的模型版本不能直接混入旧主表。

每次交接保存所用 evidence_index 和模型卡 commit/hash。论文 source 中可以标注 `CLAIM:C2 / EVIDENCE:...`，但完整状态由账本管理。

## 10. 最终交付与验收

交付实际修改后的 LaTeX 和必要补充材料；`docs/itm_rework/paper/` 下提供修改摘要、逐条 claim 账本、引用核查、编译/静态检查、待实验问题、`STATUS.md`。

验收标准：

- 不读开发日志也能看懂场景、任务边界、相容性和成功标准。
- 每个方法模块要么有证据支持，要么显式 pending；不存在隐藏在注释中的虚假完成状态。
- 正文主结果围绕三条证据，不按 Stage/V3/V4 时间线堆积。
- 同一结果可追溯到同一模型、条件、协议和评价器；head/wrists、proxy/真实观测边界清楚。
- 数字、置信区间、样本规模、失败和成本均与 evidence 一致；没有选择性把所有不利结果移走后宣称普遍成功。
- 原始引用与比较核实，编译状态真实报告；没有把草稿改写任务扩大为新实验或新投稿决策。

最低完成版本是**有清晰场景和证据占位的可维护中文研究稿**。是否最终成为方法论文或更偏经验研究，取决于 B/C 相对强简单基线的实际增量；不承诺一定发表，也不因当前负结果停止有依据的探索。
